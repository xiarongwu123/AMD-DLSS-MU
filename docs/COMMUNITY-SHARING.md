# 玩家方案统一列表与资源分享

本次仅修改代码，未部署服务器、修改线上数据或打包客户端。

## 用户交互

- 游戏库顶部及首页的玩家方案入口直接打开独立列表，无须先选择本地游戏。
- 所有玩家、所有游戏的分享按发布时间倒序展示，每页30条，支持翻页。
- 游戏配置窗口中的玩家方案页也读取同一份全局列表。
- 上传默认通用分享，可改为当前游戏专用；来源游戏保留，通用并不承诺所有游戏兼容。
- 可选读取本地实际配置，也可只发布附件或网盘链接，不要求游戏已经配置。
- 每条分享支持一个10 MB以内的附件，多个文件可打包；支持zip/7z/rar、ini/json/txt/cfg、fx/fxh/preset。DLL等配套文件可放入压缩包。
- 网盘链接使用HTTPS，提取码单独填写。详情提供打开网盘和复制链接/提取码。
- 附件独立下载，SHA256校验，Windows保存对话框选择位置；不运行附件、不解压到游戏目录。
- 参数应用时选择本地目标游戏，继续执行原组件版本、位数、会员权限、兼容条件、备份及恢复检查。
- 游戏专用旧方案仍只允许应用到相应游戏；需要跨游戏复用的新分享选通用。

## 后端兼容

复用现有 `/api/v1/presets` 服务及账户鉴权：

- `GET /api/v1/presets/all?page=1`：新版客户端明确读取所有玩家、所有游戏的全部分享。
- `GET /api/v1/presets?page=1`：兼容旧入口，也返回全站分享；旧客户端即使传入`gameKey`也不筛选或校验游戏标识。
- 旧后台没有`/all`时，客户端明确提示同步更新后台，不退回单游戏列表。
- `POST /api/v1/presets`：新增可选scope/resourceUrl/resourceCode/attachment；旧请求省略新字段仍有效。
- `GET /api/v1/presets/{id}/attachment`：需要登录，返回附件元信息和Base64内容，服务端、客户端分别验证SHA256。
- 参数分享保留原Mode；纯资源分享Mode为-1且Settings为空，不能调用参数应用。
- 列表和详情不携带附件文件体，仅携带名称、大小和摘要。
- 原每日最多5条分享限制保持不变。

启动时`CommunityPresetSchema.InitializeAsync`在同一个账户数据库中幂等增加可选字段和`CommunityPresetAttachments`附件表。旧记录默认scope=game，不改变参数或自动改为通用。附件随accounts.sqlite一起备份，不放在公开静态文件目录。

发布时先部署新版服务端，再使用新版客户端。请求上限针对方案上传提高至15 MiB（Base64编码开销）；如果前置代理有请求大小限制，方案上传路径需允许至少16 MiB。许愿池和其他接口的原请求上限保持不变。
