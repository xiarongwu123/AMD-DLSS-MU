# AMD DLSS MU 数据大屏与埋点说明

## 大屏要回答的问题

| 需要判断的事 | 本次大屏指标 | 看数时的边界 |
| --- | --- | --- |
| 有没有人访问、来自哪里 | 页面浏览、访问会话、近 5 分钟活跃会话、来源分布、每日趋势 | 浏览器统计只覆盖同意采集的访问；会话不是独立人数 |
| 官网能否带来下载 | 下载跳转请求、下载会话转化率、版本下载 | 跳转不代表文件下载完成，更不代表安装或实际使用 |
| 哪个版本被下载 | 各版本官网下载跳转、GitHub 官方累计 EXE 下载 | GitHub 包含其他渠道；不同统计范围分列展示 |
| 用户遇到什么问题 | 新增反馈、类型分布、最近反馈、待处理数量 | 用户主动报告不等于全部用户的故障率 |
| 问题有没有被跟进 | 待处理、处理中、已解决、暂不处理；反馈详情与状态修改 | 联系方式和说明只显示在已登录的反馈详情中 |
| 发布及服务是否正常 | 发行操作记录、异常登录、关键接口 5xx 比例、P95 耗时、进程运行时间与内存 | 进程指标不是整台 VPS 指标；没有样本时显示未知 |

后台入口：https://amd-dlss-mu.claude-api.cn/admin 。使用原管理员密码，支持今天、近 7 / 30 / 90 天、30 秒自动刷新和大屏模式。统计时间使用 Asia/Shanghai。

## 统计口径

- 页面浏览：用户允许匿名统计后，页面加载产生一次 `page_view`。相同 `event_id` 重试只记一次。
- 访问会话：所选期间有 `page_view` 的随机会话标识去重。第一方 `mu_visit` Cookie 有效期为 30 分钟，前台活跃时延长；不使用设备指纹，也不跨会话关联设备。
- 近 5 分钟活跃：有页面浏览记录、且最近 5 分钟收到页面事件或可见页面心跳的会话。不是实时在线人数。
- 下载跳转请求：服务端处理下载 GET 并生成 302。包含未允许浏览器统计的下载，但不为这部分请求生成会话标识。
- 下载会话转化率：所选期间既有页面浏览又发起下载跳转的会话数 / 所选期间有页面浏览的会话数。分子分母使用同一采集范围，不将全部下载次数除以部分访问样本。
- GitHub 下载：读取本仓库正式 Release 中 `AMD-DLSS-MU.exe` 附件的 `download_count`，每 15 分钟同步。保留同步时间，失败时保留旧值并提示。不能回补上线前的每日下载量。
- 常见机器人、HEAD 探测和已登录管理员的公共页面操作不计入访问/下载统计。过滤不等于完全识别自动化流量；原始请求量不是防作弊后的唯一用户数。
- 采集上线前的历史显示“未采集”，无转化分母、GitHub 未同步或接口无样本时显示“—”，不伪造历史。

## 已实现事件

| 事件 | 产生位置 / 时机 | 允许记录的业务字段 |
| --- | --- | --- |
| `page_view` | 官网四个页面，同意后加载或进入新会话 | 页面枚举、来源分类、UTM 活动标识 |
| `session_heartbeat` | 页面可见时每 60 秒 | 只更新会话活跃时间，不累计浏览量 |
| `download_click` | 直接下载按钮点击 | 页头 / 下载卡片等入口枚举 |
| `download_redirect` | `/download/file` 或兼容的旧下载路径返回跳转 | 当前版本、入口；有有效匿名会话时关联该会话 |
| `feedback_start` | 首次填写反馈表单 | 页面枚举，不采集输入内容 |
| `feedback_accepted` | 反馈成功写入持久文件后 | 类型、软件版本 |
| `feedback_rejected` | 必填内容或确认校验失败 | 受控失败原因，不记录用户输入 |
| `hash_copy` | SHA-256 复制成功 | 页面枚举 |
| `release_published` | 发行配置原子写入成功后 | 旧版本、新版本、结果 |
| `release_publish_failed` | 发行校验或保存失败 | 受控失败原因 |
| `feedback_status_changed` | 管理员保存处理状态 | 反馈编号、处理状态 |
| `admin_login_failed` | 管理密码校验失败 | 结果；不保存密码、令牌或原始 IP |
| 关键接口请求记录 | 下载、反馈、登录、发行接口响应完成 | 固定路由、状态码、耗时；不记录查询串或请求体 |

服务端生成统计时间；浏览器事件只有事件白名单和受控字段可以进入数据库，不能通过公开采集接口伪造发行审计事件。客户端 `event_id` 用于重试去重。

推广链接示例：`https://amd-dlss-mu.claude-api.cn/?utm_source=bilibili&utm_campaign=release_130`。来源支持 `github`、`bilibili`、`douyin`、`xiaohongshu`、`search`，其他来源归为“其他”。活动标识限 48 位字母、数字、下划线和连字符；不上传原始来源 URL、搜索词或 URL 查询串。

## Windows 客户端下一阶段建议

当前线上 EXE 没有接入本次统计接口。下面是建议随新版 EXE 增加的事件，不是已经可用的数据。

| 事件 | 准确触发点 | 应查看的指标 |
| --- | --- | --- |
| `app_started` | 主窗口成功显示后；排除升级辅助进程 | 匿名活跃安装数、版本分布；只有用户同意后才上报 |
| `compatibility_checked` | 兼容性检查返回后 | 通过 / 阻止原因、系统与显卡类别；阻止不是安装失败 |
| `component_install_started` | 开始一次真实配置操作，生成 `operation_id` | 安装尝试次数 |
| `component_install_completed` | 文件校验完成或操作明确失败 / 取消后 | 成功、失败、取消、耗时、结构化错误码；写入成功不代表游戏效果验证成功 |
| `restore_completed` | 原始文件恢复及完整性校验完成后 | 恢复成功率、失败阶段、耗时 |
| `update_download_verified` | 更新包大小和哈希校验通过后 | 更新下载与校验问题；不是升级成功 |
| `app_update_completed` | 新版本启动确认后，例如 `AutoUpdate.ConfirmStartup` 对应流程 | 真正升级成功率、版本迁移情况 |
| `client_error` | 明确分类的异常分支 | 版本 / 模式 / 受控错误码聚合；不上传原始异常或日志 |
| `diagnostic_exported` | 用户主动导出报告成功后 | 诊断功能使用量；报告内容仍需用户预览后主动提交 |

客户端公共字段建议为：`schema_version`、`event_id`、`operation_id`、`app_version`、`mode`、`result`、`error_code`、`duration_ms`；经独立同意后可增加粗粒度 Windows / GPU 类别，以及可重置的随机安装标识。客户端应提供默认关闭的统计开关、撤回选择、有限重试与队列容量；失败不能阻塞游戏配置和恢复。

现有 v1.3.0 的 `Diagnostics.Record` 已区分安装开始、兼容性阻止、下载校验和安装文件完成，可作为将来接入点，但诊断原文应继续保持本地。FPS 改善只在同游戏、同画质、同分辨率、同采样方式的可比测量下展示，现阶段反馈中的 FPS 只能标为“用户自报”，不能宣传为自动测得的性能提升。

## 存储、访问与运维

- 使用 Node 22 自带 SQLite，数据库为服务器 `data/analytics.sqlite`，保留现有 `data/feedback.jsonl`。反馈索引会从原文件补录，既有处理状态不会被覆盖。
- 匿名事件与会话明细保留 90 天；接口耗时记录保留 14 天；GitHub 每日快照保留 365 天；反馈及处理状态持久保存。
- 浏览器先提供“允许匿名统计 / 仅保留必要请求”的选择，页脚可修改；遵循浏览器 DNT / GPC 拒绝信号。拒绝后删除会话 Cookie，不再发送页面行为事件。
- 统计库不落盘原始 IP、浏览器完整 UA、联系方式、游戏完整路径或硬件序列号。短期内存中的来源 IP 仅用于接口限流。用户主动反馈的内容单独保存在反馈记录中，仅管理员可见。
- 所有管理数据接口沿用原密码与 HttpOnly 会话认证；写入接口验证来源。统计写入故障不阻断下载安装包和反馈原文件保存，大屏会提示采集异常。
- SQLite 数据目录保持私有，不放入 `public`。Docker 仍仅映射 `127.0.0.1:8088`，沿用现有 Cloudflare Tunnel。
- `node --test tests/analytics.test.mjs` 验证去重、统计分母、未同意不采集、授权边界、反馈状态、重启持久化和上游失败保留旧值。浏览器验收另行覆盖同意 / 拒绝、反馈处理、正文安全显示与不同屏幕布局。
