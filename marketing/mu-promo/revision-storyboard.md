# 宣传片第二版：把 MU 的用途讲清楚

状态：分镜草案。用户对“60系”的含义仍待澄清；本稿先围绕原任务中的 MU 产品整理内容，不涉及任何新显卡的发布、支持或性能宣传。暂不覆盖第一版视频。

## 第一版的问题

- 开场与收尾使用“下一局，由你掌控”“即刻开局”，没有解释 MU 是什么。
- 芯片图片、虚构游戏和城市穿行占用了说明产品操作的时间，容易被理解为显卡或游戏广告。
- “三种方案”只有名字和标签，没有展示用户如何配置、进入游戏调节、恢复文件。
- 没有交代适用条件，观看者可能误以为下载软件后所有游戏都会自动获得画质或帧率提升。

## 这次要传达的一句话

MU 是 Windows 游戏图形配置助手：把常用方案的游戏选择、组件准备和恢复入口放在一起，减少重复配置操作。

## 表现约束

- 保留 MU 黑底、荧光绿和 HUD 视觉，动画围绕按钮、状态和操作流程展开。
- 不使用虚构游戏名称、芯片特写或城市穿行充当产品收益证据。
- 使用界面动画时标注“操作流程示意”；不伪装成 Windows 实机录屏。
- OptiScaler 组件部署与游戏内实际生效分开表达，运行效果取决于具体支持条件。
- DLSS-NR 只作为方案选择入口展示；上游安装器仍有手动步骤，不写“全部一键完成”。
- Magpie 说明窗口模式和快捷键；不写“支持所有游戏”“通用帧率翻倍”。
- 没有真实测量素材时，不制作前后 FPS 对比或固定百分比提升。
- 横竖两版独立排版；中文字幕解释用途，英文标签只作辅助。

## 当前源码依据

- `src/MainForm.OptiScaler.cs:5`：组件准备、权限检查、安装和恢复记录；游戏内按 Insert。
- `src/OptiInstaller.cs:58`：下载包准备与大小、摘要校验；安装过程写入文件并记录状态。
- `src/MainForm.Product.cs:141`：完成提示明确“组件已部署”，要求在游戏内验证。
- `src/MainForm.Magpie.cs:129`：开启入口、窗口模式、Alt + Shift + A 使用步骤。
- `src/GameManagement.cs:107`：恢复时检查当前文件和备份摘要。

参考片的可借鉴部分是“技术效果 → 用户收益 → 产品”的表达结构。MU 第二版必须建立“操作 → 结果 → 恢复”的连贯叙事。
