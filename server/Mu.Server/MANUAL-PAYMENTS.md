# 人工收款与 Pro 开通

此模式不接支付接口。用户提交订单并点击“我已付款”后，会员仍保持原状；管理员必须在收款平台独立核对实际到账，再在 `/admin/orders` 输入该笔真实流水号和核对说明，确认后才会开通会员。截图、用户声称已付款、客户端请求都不能作为自动开通依据。

## 开放前

1. 在 `/admin/features` 先确定并启用至少一项真实可用的 Pro 权益。没有 Pro 权益时，购买申请不会开放。
2. 在 `/admin/plans` 创建套餐，核对价格、时长和权益说明后上架。新建套餐默认不上架。
3. 将收款说明和二维码图片放在自己管理的渠道。图片若要由客户端打开，需提供 HTTPS 地址；不要提交私人收款码到 Git 仓库。
4. 在服务端环境文件中配置 `ManualPayment__Instructions`、可选的 `ManualPayment__QrImageUrl`，最后设置 `ManualPayment__Enabled=true` 并重启服务。默认是关闭的。环境文件应只由服务账户读取，不得包含在客户端安装包或源码库中。
5. 用测试账户创建一笔订单，确认它仍是 `pending` 且会员未改变；核对后从管理后台确认，检查订单变为 `paid`、会员有效期增加。测试订单不得标成真实到账；可在独立测试数据库演练。

`ManualPayment__Instructions` 应包含实际收款方式、收款人识别信息及“付款后请保留凭证”。如果收款平台支持备注，请要求填写 MU 订单编号。管理员必须按订单编号、金额、收款账户、时间和付款凭证核对；无法确认归属时不要开通。

## 操作规则

- 订单保存创建时的套餐名称、金额、币种和时长；以后改价不会改变旧订单。
- 同一订单只能确认一次，同一收款流水号只能对应一笔订单。后台操作记录管理员、时间、核对说明和会员有效期变化。
- 未付款订单、收款二维码、转账截图或用户点击“我已付款”都不会开通 Pro。用户可在客户端刷新订单状态和会员状态。
- 退款须先在原收款平台完成，并在后台按订单与用户核对、记录处理原因和调整会员有效期；当前版本没有自动退款接口或自动撤销会员，不能把后台的“确认到账”当作退款操作。
- 发布前应准备购买条款、权益说明、退款与联系方式。不要出售尚未交付的 Pro 功能。
