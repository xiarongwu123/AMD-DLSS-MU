# 人工收款与 Pro 开通

此模式不接支付接口。用户提交订单并点击“我已付款”后，会员仍保持原状；管理员必须在收款平台独立核对实际到账，再在 `/admin/orders` 输入该笔真实流水号和核对说明，确认后才会开通会员。截图、用户声称已付款、客户端请求都不能作为自动开通依据。

## 开放前

1. 在 `/admin/features` 先确定并启用至少一项真实可用的 Pro 权益。没有 Pro 权益时，购买申请不会开放。
2. 数据库 v6 提供四档：9.9 元 / 30 天高级会员、88.8 元终身会员（含3次远程指导）、29.9 元 / 30 天高级 Plus（含1次服务）、30 元单次远程指导（不含会员）。从 v5 升级只调整默认终身套餐、增加单次服务，不改历史订单的金额或权益。升级前备份数据库；后续价格、上架与服务次数在 `/admin/plans` 管理，重新启动不会覆盖运营修改。新建其他套餐默认不上架。
3. 将收款说明和二维码图片放在自己管理的渠道。图片若要由客户端打开，需提供 HTTPS 地址；不要提交私人收款码到 Git 仓库。
4. 在服务端环境文件中配置 `ManualPayment__Instructions`、可选的 `ManualPayment__QrImageUrl`，最后设置 `ManualPayment__Enabled=true` 并重启服务。默认是关闭的。环境文件应只由服务账户读取，不得包含在客户端安装包或源码库中。
5. 用测试账户创建一笔订单，确认它仍是 `pending` 且会员未改变；核对后从管理后台确认，检查订单变为 `paid`、会员有效期增加。测试订单不得标成真实到账；可在独立测试数据库演练。

`ManualPayment__Instructions` 应包含实际收款方式、收款人识别信息及“付款后请保留凭证”。如果收款平台支持备注，请要求填写 MU 订单编号。管理员必须按订单编号、金额、收款账户、时间和付款凭证核对；无法确认归属时不要开通。

## 操作规则

- 订单保存创建时的套餐名称、金额、币种和时长；以后改价不会改变旧订单。
- 同一订单只能确认一次，同一收款流水号只能对应一笔订单。后台操作记录管理员、时间、核对说明和会员有效期变化。
- 未付款订单、收款二维码、转账截图或用户点击“我已付款”都不会开通 Pro。用户可在客户端刷新订单状态和会员状态。
- 退款须先在原收款平台完成，并在后台按订单与用户核对、记录处理原因和调整会员有效期；当前版本没有自动退款接口或自动撤销会员，不能把后台的“确认到账”当作退款操作。
- 发布前应准备购买条款、权益说明、退款与联系方式。不要出售尚未交付的 Pro 功能。

## 终身会员与配置服务

- 仅在 `GrantsMembership=true` 时，`DurationDays=0` 才表示终身会员。纯服务订单设置 `GrantsMembership=false`，付款不新增、延长或缩短会员时间。
- 订单快照保存 `ConfigurationSessions` 和 `GrantsMembership`。88.8终身含3次指导，原29.9 Plus仍为30天会员+1次服务，30元单次只发放1次指导。
- `ConfigurationSessionsUsed` 记录实际核销次数，账户返回 `remoteSessionsRemaining`。未到账订单不计次数，打开微信、查看联系方式不扣次数。
- 用户添加微信 xrwCoder 并发送订单号预约。每完成1次指导，管理员在订单页核销1次；多次服务可分次完成。表单带上已使用次数，重复或过期表单不会再扣一次；无余额及未到账订单不能核销，操作保留审计记录。
- v5历史已完成服务迁移为已用1次，避免重新赠送；历史49.9终身订单不自动变成新价或新增3次权益。新价产生新订单，不复用旧价未付款订单。
- 客户端套餐价格来自服务器；客户端预览数据不创建订单、不收款、不开通会员。部署必须同步更新服务端和 Windows 客户端。

- 终身会员权益文案：终身享用所有付费软件功能、专属功能定制、专属优化功能。定制与优化通过微信 xrwCoder 提交需求，由运营者人工提供；不冒充已内置的自动优化功能。

## 两种收款码

原始图片私下保存在 `server/private/payments/wechat.jpg`、`alipay.jpg`，已被 Git 忽略。构建时嵌入服务器，订单创建或查询的已登录响应提供图片数据；不放进公开静态目录或源码仓库。部署前保留这两个私有文件。客户端可切换微信与支付宝，固定收款码不包含订单金额，需要用户填写金额、备注订单号，人工核对到账。原 `ManualPayment__QrImageUrl` 单码配置仍可作为没有私有图片时的兼容路径。

## 高级 Plus 与远程服务权限

- 四档名称和价格以本页v6说明为准。保留三个原会员ID，另加 `mu-remote-once`；单次指导不附带会员，不参与Plus时长计算。
- 软件权限继续使用兼容旧客户端的 `tier=pro`，账户快照提供 `membership.kind`（`advanced` / `lifetime` / `plus`）、`plusExpiresAt` 和 `remoteSessionsRemaining`。
- `services.remote` 需功能启用，并满足有效Plus或剩余指导次数大于0。普通账户购买单次指导后可以预约，但不会解锁高级软件内容；终身会员使用完3次指导仍保留终身软件权限。
- Windows 点击远程服务时重新向服务端验证权限；客户端失去服务权益后关闭联系弹窗。该权限即使被管理员误设为普通等级，仍受服务端Plus/服务余额条件限制。
- 原已确认的29.9服务订单可识别为Plus；服务交付仍按原订单记录一次，不因入口开放重复增加服务次数。服务端与Windows客户端需要同步部署；本次代码修改不代表已经部署。
